# 탐험형 진행 및 모바일 입력 수정

사용자 피드백: 모바일 입력칸 탭으로 키보드가 뜨지 않으며, 입장 자동 대화와 HUD 순간이동 때문에 맵 탐험이 불필요해졌다.

## 수정

- 1.6초 입장 자동 실행 제거. 성공 대기/관람 예절 입장 자동 대화 제거. 낮 맵의 획득한 엔딩만 예외.
- HUD 원격 재개/맵 이동 제거. 임무 위치 안내는 메시지만 표시. 별도 주변 NPC 대화는 검증한 NPC 좌표의 가로·세로 2타일 이내에서만 실행.
- F와 모바일 액션 버튼도 박물관에서는 오래된 상호작용 키 대신 현재 가까운 NPC를 조회.
- 사유의 방 반가사유상 ① 첫 상호작용에서 프롤로그 → 첫 대화, 완료 후 로비 이동. 맵 입장만으로는 시작하지 않음.
- 성공 대화 중 닫은 경우 해당 NPC를 다시 찾아가면 저장된 성공 대화 재개. 성공/퀴즈 판정 조건과 필요한 완료 후 이동은 유지.
- 로비(5) 안내로봇: 편집기에서 `(38,50)` 로봇 아래 충돌 타일 확인. 상호작용 중심 `(38,49)`, 바로 아래 `(38,51)`에서 버튼/F로 이용 가능.
- 로비(4) 오른쪽 신라실 문: 편집기에서 통행 타일 `(98,45)` 확인. 해당 위치에 `addOnTileTouched` → `spawnAtMap` 연결. 저장된 맵 타일/장식은 변경하지 않음. `putTileEffect` 포털 방식은 현장 통과 시 이동하지 않아 사용하지 않음.

## 모바일 입력

글자 선택 버튼은 제거했다. HTML 입력칸의 폰 키보드 미표시 원인은 사용자 기기에서 직접 재현하지 못했으므로 확정하지 않는다.

- 모바일: 입력칸 탭 → 공식 `player.showPrompt` 입력 UI → 키보드로 자유 입력 → 결과를 미션 답안으로 반영 → 정답 확인. 답안은 정답을 자동 제공하지 않으며 서버 판정을 통과해야 완료된다.
- 데스크톱: 일반 text input, 터치/포인터 이벤트에서 동기 focus. 한글 조합 Enter 중복 제출 방지, 빈 값 제출 차단.
- 서버 응답/오답으로 같은 입력칸 DOM을 다시 만들지 않아 포커스·한글 조합·입력값을 유지한다.
- 기본 입력창 응답은 현재 게임 세션인지 검증한다. 닫기/맵 이탈/재시작 후 오래된 입력 결과는 무시한다.
- `showWidget`의 `popup` 정렬은 시험 배포 후 실제 화면이 표시되지 않아 폐기했다. 최종 버전은 검증된 `middle` 정렬과 모바일 ZEP 기본 입력 UI를 사용한다.

공식 입력 API: [ZEP ScriptPlayer methods / showPrompt](https://docs.zep.us/zep-script/zep-script-api/scriptplayer/methods).

## 검증 범위

- 자동 테스트 28개, TypeScript, 빌드 통과.
- 실제 고구려실 재입장 시 게임/대화 없음. 먼 위치에서 주변 NPC 버튼은 거리 안내만 표시. NPC 앞에서는 대화 및 미션 정상 표시, 런타임 진단 오류 `[]`.
- 위젯 게시값 `1789344734`, 앱 `53Xe2L`에서 최종 입력창 표시 확인. 이후 문 이동 콜백 교정만 추가 게시.
- 문 콜백 게시 후 실제 `(98,46)`에서 위로 걸어 `(98,45)`를 통과해 `r7aeam` 이동 확인. 도착 후 NPC/게임 위젯이 자동 표시되지 않음.
- 모바일 기기의 소프트 키보드 표시 성공은 사용자 확인 대기. 이 기록은 모바일 실기기 검증 완료를 뜻하지 않는다.
