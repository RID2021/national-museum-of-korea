# 박물관 대사 및 맵 검증 - 2026-09-14

## 검증 범위와 방법

사용자가 제공한 국립중앙박물관 시놉시스 PDF 3-8쪽을 렌더링해 읽고,
현재 데이터의 8명, 29장면, 총 77개 대화 페이지를 실제 ZEP 위젯에서 확인했다.
원문의 대사는 유지돼 있으며 페이지 분할, 힌트의 내레이션 표시, 명단의 대화창 표시는 UI용 구성이다.

대상: 스페이스 `nLP9zE`, 앱 `53Xe2L` (`seoul2_ museum`).
일반 사용자의 진행 상태를 초기화하거나 퍼즐 완료 보상을 부여하지 않았다.
짧은 자동 키 입력으로 장거리 이동을 재현하기 어려워, 관리자 본인만 접근 가능한
타일로 이동하는 진단 명령을 사용했다. 아래 7개 오브젝트는 이후 실제 F키로 실행했다.
따라서 전 구간을 입구부터 도보로 완주한 결과가 아니라, 맵별 접근 지점과 실제 상호작용 검증이다.
로봇은 영역 F키 및 영역 밖 `(42,16)`에서 W키로 들어가는 자동 진입 모두 확인했다.

## 발견하고 수정한 코드 결함

1. 입장 오류: `portalGates.ts`의 `const alias = ScriptApp as ...`가 배포 과정에서
   ZEP의 `App`으로 변환되지 않아 `ScriptApp is not defined` 예외를 발생시켰다.
   `ScriptApp.mapHashID` 직접 참조로 변경했다. 수정 후 내부 7개 맵의 입장 진단 오류 배열은 모두 비어 있었다.
2. 에디터 F키 무응답: 순수비에서 실제 이벤트가 `{layer:5,x:39,y:27,key:""}`로 수신됐다.
   기존 key 전용 처리로는 param1 대화값을 읽을 수 없었다. key로 처리하지 못한 경우에만
   이벤트의 레이어와 정확한 좌표에 해당하는 type-21 오브젝트의 param1을 읽도록 수정했다.
3. 빈 작업 위젯: 작업 이미지가 없는 박물관 맵에서도 투명 iframe이 생성돼 클릭 포커스를 받았다.
   이미지가 없으면 기존 작업 위젯을 정리하고 새 위젯은 만들지 않도록 했다.

회귀 테스트 16개 통과. `npm run deploy`가 테스트, 빌드, 패키징, 앱 ID 검증, 게시를 순서대로 수행한다.
대화 전체 검증 후 마지막 빌드는 빈 위젯 처리와 진단 출력 정리만 변경했으며 대본/대화 라우팅은 동일하다.
최종 게시본(`appUpdatedAt=1789318617`)에서 순수비에 재접속해 입장 오류 없음,
빈 Task Widget 미생성, 실제 F키 대화 열기, F키 한 번에 1/4 → 2/4 한 쪽 진행을 재확인했다.
점검 후 대화창을 닫고 `#museum-audit-off`로 본인 진단 추적을 껐다.

## 유지보수용 관리자 진단

- `#museum-check`: 현재 위치, 입장 예외, type-21 오브젝트 설정을 본인에게만 표시하고 F 이벤트 추적 활성화.
