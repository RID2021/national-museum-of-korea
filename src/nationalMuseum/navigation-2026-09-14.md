`spawnAtMap(ScriptApp.spaceHashID, mapHashId)`로 캐릭터를 이동시킨다. 새 탭 또는 위젯 URL 변경은 사용하지 않는다. 로비를 건너뛰지 않는다.

편집기에서 기존 이동 타일의 목적지를 직접 확인한 경로: 밤→사유, 사유→로비(1), 로비(1)→고구려, 고구려→로비(2), 로비(2)→백제, 백제→로비(3), 로비(3)→가야, 가야→로비(4), 신라(1)→신라(2), 신라(2)→로비(5). 목적지는 맵 스폰 영역이었다.

로비(4)는 오른쪽 신라실 입구까지 화면을 이동해 살폈지만 파란 이동 타일을 찾지 못했다. 전체 타일 데이터의 부재를 확정한 것은 아니며, 수동 출입 동선은 추가 확인이 필요하다. 로비(5)의 종료는 카드 미션의 프로그램 이동으로 처리한다. 이번 작업에서 기존 이동 타일이나 오브젝트 배치는 변경하지 않았다.

## 성공 콜백 계약과 안전 조건

실제 게임 판정 구현 시 아래 ID로 기존 서버 완료 핸들러에 연결해야 한다. 아직 이 ID를 발생시키는 박물관 게임은 없다. 대화의 `quiz`는 게임이 아닌 질문 표시다.

1. `museum-hou-relations`
2. `museum-baekje-bricks`
3. `museum-gaya-iron`
4. `museum-hwangnam-crown`
5. `museum-jinheung-locations` — 퍼즐과 모든 위치 확인이 모두 끝난 뒤 발생
6. `museum-etiquette`
7. `museum-artifact-cards`

올바른 스페이스·출발 맵·이전 미션 완료를 검사하고 중복 완료 콜백을 무시한다. 성공 대화를 닫으면 즉시 이동하지 않으며 재접속 시 대기 중인 성공 대화를 복원한다. 관리자 성공 대사 미리보기는 완료 상태를 만들지 않는다. 완료 상태는 기존 플레이어 저장소의 다른 항목을 보존하며 `museumJourney`에 저장한다.
